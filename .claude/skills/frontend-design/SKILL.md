# Frontend Design Skill

Stack: **shadcn/ui + Tailwind CSS v4 + clsx**

---

## Design Philosophy — read this first

You tend to converge toward generic, "on distribution" outputs. In frontend design this creates what users call the **"AI slop" aesthetic**. This is the default failure mode — avoid it actively on every task.

**What AI slop looks like:**
- Space Grotesk or Plus Jakarta Sans as the "creative" font choice
- Purple/indigo gradient on white or near-white background
- Slate gray card with `rounded-lg`, subtle shadow, and centered content
- Every element the same border radius
- Uniform muted gray text hierarchy with one blue accent
- Predictable 3-column grid or hero + features layout

**What to do instead:**
Before writing a single line of code, commit to a bold, specific aesthetic direction. Pick ONE tone and execute it fully:

| Tone | What it means in practice |
|---|---|
| **Editorial** | Oversized serif headlines, tight leading, asymmetric layout, ink-on-paper palette |
| **Brutalist** | Raw structure visible, stark contrast, heavy borders, monospace, zero decoration |
| **Luxury** | Generous whitespace, gold/cream/obsidian, refined micro-typography, slow animations |
| **Retro-futuristic** | CRT scanlines, terminal green or amber, grid overlays, glitch effects |
| **Industrial** | Texture-heavy, muted earth tones, utilitarian type, exposed grid |
| **Playful** | Expressive color, bouncy motion, irregular shapes, illustrated accents |
| **Organic** | Flowing shapes, earthy palette, handwritten accents, soft shadows |

**Critical rule on convergence:** Every component generated by this skill must look visually distinct from the previous one. If the last component used a dark background with indigo accent — this one should not. Actively vary: light vs dark lead, serif vs sans, minimal vs expressive, warm vs cool. Sameness is failure.

**The test:** Would someone look at this and immediately know it was AI-generated? If yes — redesign.

## Step 1 — Theme detection

Before writing any code, check if a theme already exists:

```bash
# Check for shadcn theme (CSS variables in globals.css)
grep -n "\-\-primary\|--background\|--foreground\|--accent" src/app/globals.css src/index.css 2>/dev/null | head -20

# Check tailwind config for custom tokens
cat tailwind.config.ts 2>/dev/null | head -60

# Check for next-themes or similar
grep -r "ThemeProvider\|next-themes\|useTheme" src --include="*.tsx" -l | head -5
```

**If shadcn theme exists** → read `globals.css` CSS variables, use them via Tailwind semantic classes (`bg-background`, `text-foreground`, `bg-primary`, etc.). Never hardcode colors or override existing variables.

**If no theme exists** → ask ONE question before writing any code:

> "Немає теми в проекті. Який приблизний primary колір хочеш використати? (hex, назва або настрій — наприклад 'темно-синій', 'смарагдовий', 'теплий помаранчевий')"

Then generate a full shadcn-compatible theme (see Step 2).

## Step 2 — Theme generation (if no theme)

Generate shadcn-compatible CSS variables in `src/app/globals.css` (or `src/index.css`).
All values use **HSL without the `hsl()` wrapper** — this is shadcn convention.

```css
@import "tailwindcss";

@layer base {
  :root {
    --background:        <h> <s>% <l>%;
    --foreground:        <h> <s>% <l>%;
    --card:              <h> <s>% <l>%;
    --card-foreground:   <h> <s>% <l>%;
    --popover:           <h> <s>% <l>%;
    --popover-foreground:<h> <s>% <l>%;
    --primary:           <h> <s>% <l>%;
    --primary-foreground:<h> <s>% <l>%;
    --secondary:         <h> <s>% <l>%;
    --secondary-foreground:<h> <s>% <l>%;
    --muted:             <h> <s>% <l>%;
    --muted-foreground:  <h> <s>% <l>%;
    --accent:            <h> <s>% <l>%;
    --accent-foreground: <h> <s>% <l>%;
    --destructive:       <h> <s>% <l>%;
    --destructive-foreground: <h> <s>% <l>%;
    --border:            <h> <s>% <l>%;
    --input:             <h> <s>% <l>%;
    --ring:              <h> <s>% <l>%;
    --radius:            0.5rem;

    /* Custom display/body fonts */
    --font-display: '<DisplayFont>', serif;
    --font-body:    '<BodyFont>', sans-serif;
  }

  .dark {
    --background:        <h> <s>% <l>%;
    /* ... all tokens redefined for dark mode */
  }
}
```

Extend `tailwind.config.ts` to expose font variables:

```ts
// tailwind.config.ts
import type { Config } from 'tailwindcss'

export default {
  darkMode: ['class'],
  content: ['./src/**/*.{ts,tsx}'],
  theme: {
    extend: {
      fontFamily: {
        display: ['var(--font-display)'],
        body:    ['var(--font-body)'],
      },
    },
  },
} satisfies Config
```

Font import in `globals.css` (Google Fonts via `@import`):

```css
@import url('https://fonts.googleapis.com/css2?family=<DisplayFont>:wght@400;700&family=<BodyFont>:wght@400;500&display=swap');
```

## Step 3 — Dark mode setup

Use `next-themes` for Next.js or a minimal custom hook for Vite/React:

```tsx
// next.js: app/layout.tsx
import { ThemeProvider } from 'next-themes'

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" suppressHydrationWarning>
      <body>
        <ThemeProvider attribute="class" defaultTheme="system" enableSystem>
          {children}
        </ThemeProvider>
      </body>
    </html>
  )
}
```

```tsx
// vite/react: hooks/useTheme.ts
import { useState, useEffect } from 'react'

type Theme = 'light' | 'dark'

export function useTheme() {
  const [theme, setTheme] = useState<Theme>(() => {
    if (typeof window === 'undefined') return 'light'
    return (localStorage.getItem('theme') as Theme)
      ?? (window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light')
  })

  useEffect(() => {
    document.documentElement.classList.toggle('dark', theme === 'dark')
    localStorage.setItem('theme', theme)
  }, [theme])

  return { theme, toggle: () => setTheme(t => t === 'light' ? 'dark' : 'light') }
}
```

shadcn uses `.dark` class on `<html>` — always `classList.toggle('dark', ...)`, never `data-theme`.

## Step 4 — Component implementation rules

### Class composition with clsx

Always use `clsx` for conditional classes:

```tsx
import { clsx } from 'clsx'
// or if using tailwind-merge:
import { cn } from '@/lib/utils' // shadcn's cn = clsx + twMerge

// ✅ correct
<div className={cn('rounded-lg bg-card p-4', isActive && 'ring-2 ring-primary', className)} />

// ❌ never
<div className={`rounded-lg bg-card p-4 ${isActive ? 'ring-2 ring-primary' : ''}`} />
```

### shadcn component usage

- Prefer shadcn primitives (`Button`, `Card`, `Dialog`, `Input`, etc.) over custom from scratch
- Extend via `className` prop — never modify shadcn source files directly
- Use `variant` and `size` props before reaching for custom classes
- For unsupported variants, create a wrapper, not a fork:

```tsx
// ✅ extend via wrapper
function DangerButton({ className, ...props }: ButtonProps) {
  return (
    <Button
      variant="outline"
      className={cn('border-destructive text-destructive hover:bg-destructive hover:text-destructive-foreground', className)}
      {...props}
    />
  )
}
```

### Tailwind semantic classes — always use, never raw hex

```tsx
// ✅ semantic — respects light/dark automatically
className="bg-background text-foreground border-border"
className="bg-primary text-primary-foreground"
className="bg-muted text-muted-foreground"
className="bg-card text-card-foreground"

// ❌ never hardcode
className="bg-[#1a1a2e] text-white"
style={{ color: '#6366f1' }}
```

### Typography

```tsx
// Apply font families via Tailwind
<h1 className="font-display text-4xl font-bold tracking-tight" />
<p  className="font-body text-base text-muted-foreground" />
```

- `font-display` → headings, hero text, labels with character
- `font-body` → body copy, inputs, descriptions
- NEVER use Inter, Roboto, Arial, or system-ui as the display font
- Choose fonts with personality: editorial, geometric, humanist, slab serif, monospace

### Motion

```tsx
// Simple: CSS transitions via Tailwind
className="transition-colors duration-200 hover:bg-accent"

// Complex: Motion library (motion/react)
import { motion } from 'motion/react'

<motion.div
  initial={{ opacity: 0, y: 16 }}
  animate={{ opacity: 1, y: 0 }}
  transition={{ duration: 0.4, ease: 'easeOut' }}
/>

// Page load stagger — more impact than scattered micro-interactions
{items.map((item, i) => (
  <motion.div
    key={item.id}
    initial={{ opacity: 0, y: 12 }}
    animate={{ opacity: 1, y: 0 }}
    transition={{ delay: i * 0.06, duration: 0.35 }}
  />
))}
```

### Backgrounds & depth

```tsx
// Add atmosphere — not flat bg-background
className="bg-gradient-to-br from-background via-muted/30 to-background"

// Noise texture overlay (add to globals.css)
// .noise::after { background-image: url("data:image/svg+xml,..."); opacity: 0.03; }
```

- Dark mode: deep background, not pure black — use `hsl(224 20% 6%)` range
- Light mode: off-white with warmth — `hsl(40 20% 97%)` range
- One unexpected accent that creates energy in both modes

### Anti-patterns — never

- Hardcoded hex or rgb colors in className or style props
- Modifying shadcn component source instead of wrapping
- Template literal class concatenation instead of `cn()`
- Purple gradient on white — the most clichéd AI aesthetic
- Same Space Grotesk + slate palette on every component
- Every element the same `rounded-lg` — vary radius intentionally

## Step 5 — Component prop conventions

```tsx
import { clsx } from 'clsx'
import { cn } from '@/lib/utils'

interface MyComponentProps {
  className?: string      // always support className for composition
  children?: React.ReactNode
  variant?: 'default' | 'subtle' | 'outlined'
}

export function MyComponent({ className, children, variant = 'default' }: MyComponentProps) {
  return (
    <div
      className={cn(
        'rounded-md p-4 transition-colors',
        {
          'bg-card text-card-foreground':        variant === 'default',
          'bg-muted/50 text-muted-foreground':   variant === 'subtle',
          'border border-border bg-transparent': variant === 'outlined',
        },
        className,
      )}
    >
      {children}
    </div>
  )
}
```

## Design thinking before coding

Before writing any component, answer internally:

1. **Tone** — pick ONE: brutalist / editorial / luxury / playful / industrial / organic / retro-futuristic
2. **Memorable detail** — font pairing, hover effect, background texture, unusual layout
3. **Lead mode** — design for both light/dark but commit to one as the primary experience
4. **Motion** — one well-placed staggered reveal > ten scattered micro-interactions

Execute the vision fully. Generic is never acceptable.
